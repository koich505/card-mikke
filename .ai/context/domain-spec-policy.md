# Domain Specification Policy

## Goal

Domain Specification defines concepts, responsibilities, boundaries, relationships, invariants, scenarios, and open questions before implementation.

## Non-goals

Do not produce:

- DB schema
- Tables
- Columns
- SQL
- Prisma schema
- ORM model
- JSON schema
- API design
- ER diagram
- UI design
- Class design

## Concept definition format

For major domain concepts, describe:

- Definition
- Responsibility
- Identity
- Lifecycle
- Relationships
- Invariants
- Boundaries
- Examples
- Counterexamples
- Temporal behavior
- Evidence requirements
- Open questions

## Key boundaries

Always check:

- Actor / Organization / Role
- Product / Offering / Variant
- Payment Instrument / Payment Scheme / Funding Method
- Regulatory Registration / Legal Classification
- Member / External Membership / Account
- Reward / Economic Flow
- Product Lifecycle / Feature Lifecycle
- Source / Evidence / Domain Fact

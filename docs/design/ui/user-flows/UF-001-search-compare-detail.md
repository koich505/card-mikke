# UF-001: 条件入力から検索・比較・カード詳細へ進む

Status: Approved primary flow; interaction details under UI dialogue  
Requirements baseline: `docs/spec/requirements/07-approval.md`（2026-08-10 Approved）  
Decision date: 2026-08-10

## Goal

未登録または登録利用者が、自身の年間利用額と利用先を指定し、3分以内を目標に比較可能な候補を3件以上見つけ、同一条件で比較してカード詳細と根拠を確認する。

## Primary users

- U-001: 初めてクレジットカードを作る個人
- U-002: ポイント・特典・利用Serviceを重視する個人

## Related Requirements

- FR-003–FR-006
- FR-010、FR-012–FR-016
- FR-017–FR-020、FR-023
- FR-029、FR-039
- AC-001、AC-002、AC-005–AC-012、AC-014、AC-015、AC-020

## Preconditions

- Account登録は不要である。
- 登録利用者に保存済みProfileがある場合は、保存値を初期値として識別可能に反映する。
- UI Mockは合成Fixtureだけを使用し、検索・算定・保存・申込の本番処理を行わない。

## Trigger

利用者がホームの`条件からカードを探す`を開始する。

## Main flow

| Step | User action | UI response | Traceability |
|---|---|---|---|
| 1 | ホームの主要Actionからカード探しを開始する | 注目カード・特集・新着とは区別された条件検索入口で、年間利用額を最初の必須入力として示し、Accountなしで利用できることを伝える | FR-010, AC-001 |
| 2 | 年間利用額を入力する | 入力値、単位、Error、利用先内訳との差額を理解できるようにする | FR-004, FR-012, AC-005 |
| 3 | 利用先カテゴリと金額を追加する | 11カテゴリを提示し、カテゴリだけまたは架空の企業・Serviceを選択できるようにする | FR-012, AC-006 |
| 4 | 必要に応じて企業・Serviceを指定する | カテゴリ全体の仮定と個別指定を区別し、内訳合計を更新する | FR-012, AC-005, AC-006 |
| 5 | 入力内容を確認して検索する | 入力の整合性を検証し、処理中状態を示す | FR-039, AC-005 |
| 6 | 検索結果を確認する | 年間正味還元額が高い順を基本とし、条件、件数、初年度／通常年、算定状態を示す | FR-005, FR-006, FR-013, FR-014, FR-023, AC-007, AC-009, AC-010 |
| 7 | 必須Filterを変更する | 適用中条件を常に識別でき、利用者の操作なしに条件を緩和しない | FR-013, AC-010, AC-011 |
| 8 | 3枚を比較候補に追加する | 選択状態、選択枚数、最大5枚、解除Actionを示す | FR-029, AC-012 |
| 9 | 比較を開く | 同一入力条件で、必須比較項目、内訳、算定状態、確認日を並べる | FR-016, FR-029, AC-012 |
| 10 | 1枚のカード詳細を開く | 商品条件、内訳、計算対象外、仮定、確認日、適用期間、Evidenceを示す | FR-016–FR-018, FR-020, AC-014 |
| 11 | 申込導線を確認する | 広告・Affiliate関係と、申込前に公式情報を確認する必要性をAction前に示す | FR-019, AC-015 |

## Completion

- 利用者が比較したカードの違いと算定状態を説明できる。
- 利用者が年間正味還元額を確定額ではなく目安として理解できる。
- 利用者が確認日、Evidence、申込前の公式確認方法へ到達できる。

## Alternate paths

### A-1: Profile値を一時変更する

1. 保存済みProfile値が入力欄へ反映される。
2. 利用者が今回だけ値を変更する。
3. UIは`今回の検索だけに使用`と示す。
4. Profile保存は別の明示Actionとし、暗黙に更新しない。

Traceability: FR-002、FR-003、AC-002

### A-2: キーワードから開始する

1. 利用者がカード名、発行会社名、ポイント名または利用先名を入力する。
2. 関係する候補を示す。
3. 条件入力がない場合、算定に必要な情報が不足していることを示し、条件追加へ誘導する。
4. 対象が明確な場合はカード詳細へ進める。

Traceability: FR-028、AC-011

### A-3: 記事から比較へ合流する

1. 利用者が用途別記事または単一カード特集を読む。
2. 対象カードと選定理由、確認時点、公式Source、広告関係を確認する。
3. 対象カードを比較候補へ追加するか、関連条件で検索する。

Traceability: FR-007–FR-009、FR-019、FR-031、AC-015、AC-016

## Validation and recovery paths

### V-1: 利用先内訳が年間利用額を超える

- 検索を実行しない。
- 超過額と修正対象をTextで示す。
- 入力値を保持したまま、該当項目へFocusを移して訂正できるようにする。

### V-2: 検索結果が0件

- Emptyとして0件を示し、ErrorやDisclosure Statusの`unknown`と区別する。
- 緩和可能な条件を示すが、自動変更しない。
- 条件変更またはキーワード再入力へ戻れるようにする。
- 招待制・受付停止カードを無断で追加しない。

### V-3: 一部の候補だけ算定に失敗する

- 成功した候補をPartial状態で表示する。
- 失敗した候補と理由、再試行Actionを区別する。
- 失敗値を推測で補完しない。

### V-4: 算定不完全な候補がある

- 候補を順位から除外しない。
- 確認済み要素だけの金額、含めなかった要素、過小評価の可能性、順位変動可能性を示す。

### V-5: 変更確認中の値がある

- 過去に承認された値を使用していること、確認日、暫定結果、順位変動可能性を示す。
- 一度も確認できていない値を使う算定不完全状態と区別する。

### V-6: Profile反映に失敗する

- 保存値を利用できなかったことを示す。
- 手入力を利用可能にし、検索・比較を継続できるようにする。

## Back, cancel, and clear behavior

- 検索結果から条件入力へ戻る場合、現在の入力値とFilterを保持する。
- 比較から検索結果へ戻る場合、比較候補を保持する。
- 比較候補は個別解除と全解除を提供する。全解除は確認を伴う候補とする。
- Filter解除は個別解除とすべて解除を提供し、結果件数の変化を通知する。
- 入力途中でHomeへ戻る場合、UI Mockでは保存を保証しない旨を示す。永続化は行わない。

## Required states for the mock

- Default
- Loading
- Empty
- Validation Error
- Recoverable Error / Retry
- Partial result
- Complete calculation
- Incomplete calculation
- Change under review
- Disclosure Status: `unknown`、`undisclosed`、`partially_disclosed`、`disclosed`

Disclosure Statusは一般画面状態のUnknown、Loading、Empty、Error、Partialと視覚・文言の両方で区別する。

## Accessibility expectations

- 条件入力、Filter、比較選択、比較、カード詳細をKeyboardだけで完了できる。
- Error summaryと各入力Errorを関連付け、修正対象へFocus移動できる。
- 検索結果件数、Filter適用、比較候補追加、Loading完了を支援技術へ通知する。
- 比較状態、算定状態、確認中状態をColorだけで表現しない。
- Mobileの固定操作領域がZoom時またはSoftware Keyboard表示時に重要情報を隠さない。

## Approved interaction decisions

- 条件入力は同一Page内の段階表示とし、年間利用額、利用先、確認の順に進む。
- 前後移動しても入力値を保持する。
- 利用額は年額入力を基本とし、月額換算機能を追加しない。
- 利用先内訳の合計と残りの`その他の利用`を常時確認可能にする。
- 11カテゴリをすべて選択可能にし、選択したカテゴリだけ金額・企業Service入力を展開する。
- カテゴリのみ指定した場合は、カテゴリ内の確認済み最良条件を使う目安であることを明示する。
- 検索結果は通常年を主表示、初年度を副表示とし、両者を同時に区別して確認可能にする。
- Desktopの検索結果は左側Filter、右側Resultの構成とする。
- MobileのFilterは全画面Dialogとし、適用、取消、全解除をKeyboardで操作可能にする。
- 適用中Filterは検索結果上部で個別解除できるようにする。
- 比較候補は検索結果Card内から追加・解除し、選択中は画面下部の操作領域に件数と`比較する`Actionを示す。
- 比較上限は5枚とし、上限到達時に追加できない理由と解除方法を示す。
- Desktop比較はカードを列、項目を行とする表とし、カード名・年間正味還元額・項目名を追従表示する。
- Mobile比較は項目ごとにカードを縦表示し、`違いがある項目のみ表示`とカードの削除・入替を提供する。
- 算定内訳とEvidenceはPage内で開閉し、算定状態、確認日、重要な注意事項は常時表示する。
